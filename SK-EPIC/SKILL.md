# SK-EPIC — Epic Generation (Jira-quality)

## Purpose
An Epic is a **business outcome package** a product owner can understand in 60 seconds:
why it exists, what is in/out, and which stories deliver it.

## Inputs
- stories[]
- capabilities[]
- clustering_policy (default: by capability)

## Outputs
- CS: `artifacts/cs/cs_epics.json` **required**
- TS: `artifacts/ts/ts_epics.json` **required**
- Nested Markdown **required**:
  - `artifacts/{cs|ts}/epics/<EPIC-ID>/epic.md`
  - stories live under `.../stories/<STORY-ID>.md`

## Clustering rules
- Epic groups related stories sharing one business outcome
- **1 story is OK** when atomic; **multiple** when actors/flows truly differ
- Prefer capability / user journey / bounded context
- Every story has `epic_id`; epic lists `story_ids`
- Anti-pattern: fake splits **or** mega-story dumping unrelated FRs

## HARD quality bar

### Epic title
- Outcome-oriented noun phrase or short outcome — e.g. `CCDS User Access & Session Management`
- Forbidden: `Operate …`, `Capability CAP-00x`, raw IDs only

### Business objective
- Measurable/observable outcome for the business (who benefits + what succeeds)

### Epic narrative (in Markdown, required)
Include short sections (tables + short prose OK):
1. **Why this epic** — business problem/value in 2–4 sentences
2. **What users/systems can do when done** — bullet outcomes
3. **Scope In / Scope Out** — explicit
4. **Child stories** — table with Story ID, Title, Why this story (one line)
5. **Success metrics** — how PO knows epic is done (observable)

### Forbidden epic text
- “Clustered by capability; one child story is sufficient because evidence indicates…”
- Scope Out that only says “AC/tests generated by other agents”

## Procedure
1. Decide story boundaries from evidence; split only when real
2. Cluster; write outcome title + objective + why/value
3. Write scope in/out and child-story plan with “why this story”
4. Ensure `epic_id` / `story_ids` consistency
5. Write nested `epic.md` from `templates/epic.md` (enhanced sections)
6. Self-check: a PO can pitch the epic without opening JSON IDs

## Must not
Invent fake multi-story splits; bury the outcome under legacy ID lists.
